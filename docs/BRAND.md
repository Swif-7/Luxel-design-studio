## 名称

**Luxel** ＝ `lux`（光）× `pixel`（像素）＝ **一个光的单位**。

| | |
|---|---|
| 读音 | LUX-el，两音节，重音在前 |
| 中文 | 勒克塞（非正式场合可用；正式文件保留英文原名） |
| 书写 | 首字母大写 `Luxel`。**不写** LUXEL、luxel、LuXel |
| 词性 | 专有名词，不加冠词。「用 Luxel 做的」，不是「用一个 Luxel」 |
| 全称 | `Luxel` + 后缀（如 Luxel Design），用于域名、工商与检索场景以区隔 Luxel Corporation。**后缀未定** |

### 品牌名与全称是两件事

标志、页眉、口头称呼一律只用 **`Luxel`** —— 加后缀会稀释记忆点，而记忆点正是选这个名字的理由。
后缀只出现在需要消歧的地方：域名、工商注册、应用商店名称、SEO 标题。

这样处理的好处是**实现端不用改**：页眉保持 `Luxel`，只有域名和注册信息带后缀。

选它的理由：这是个自造词。真词（Gamut、Facet、Flux）自带别人的含义，标只能挤在旁边；
自造词是空的，谁先填谁拥有。而且 `lux × pixel` 这层意思对设计师和图形程序员都是一秒懂，
名字本身就把产品讲清楚了，不需要副标题。

> **历史**：项目曾用名 FLUX，因与 Black Forest Labs 的 FLUX 图像模型在生成式视觉类目严重撞名而弃用。
> 本地存储键 `flux-state-v3` **刻意保留未改** —— 改名会让已有用户保存的参数全部丢失，而该键对用户不可见。

### 命名架构

```
Luxel                    站点 / 品牌
└── Rheo                 站内工具：实时流动着色器工作台
    └── 丝绸流动 / 交汇融流 / 双涡卷流 / 层流漫涌   工具内的效果
```

工具名独立于站名，不做 `Luxel Rheo` 这种连写。正式介绍写「Rheo，Luxel 旗下的着色器工作台」。
新工具沿用同一层级：短的自造词或真词均可，但**不得再用光学 / 流体类名词**，那一层留给效果名。

## 标志

### 共同原则

- 单色，使用 `currentColor`，深浅模式自动反色，**不做两套文件**
- 64 栅格构造，四边等距
- 不与彩色画布争视线 —— 标志出现在界面 chrome 里，画布里的作品才是颜色的主角

### 已选定：B 阶梯格

一个像素格，格内的光被量化成四级 —— 把 Luxel 的字面意思直接画了出来：一格 = 一个 pixel，四级灰 = 光被测量、被离散化。

对摄影和印刷出身的设计师，这是灰阶梯尺（step wedge）的直接引用：圈内人一眼认得，圈外人只觉得好看。
它也是五组里**唯一不依赖字母 X** 的，因此可以脱离字标独立放大成整面图形，是周边和包装上延展性最好的一组。

```
视框 64 × 64
方格   12 → 52（边长 40，四边留白 12）
四象限 各 20 × 20，相邻无间隙
灰阶   左上 100%   右上 62%
       左下 38%    右下 16%
```

灰度递减方向为**左上 → 右下**，即光自左上入射后的衰减。此方向不可镜像或旋转。

**最小尺寸**：16 px 及以下改用三格实心版（左上 100%、右上与左下各 45%、右下留空），
四级灰在该尺寸会糊成一团。favicon 即采用此版本。

**纯线稿场景**（刻印、烫金、单色丝印）无法表现灰阶，需另做描边分格版 —— 尚未设计。

### 未采用的四组（构造存档）

另外四组均从「X」长出来 —— X 本身就是交叉：光线在焦点处相交、`lux × pixel` 的乘号、栅格线的交点。
最终未采用，因为 B 不依赖字母即可成立，脱离字标也能独立放大。

| 组 | 概念 | 构造 | 栅格边距 |
|---|---|---|---|
| **A 焦点 X** | 四束光收拢交于一点 | 光束长 26，末端半宽 6，按垂直轴线切齐 | 9.37 |
| **C 光栅 X** | 光 × 栅格，交叠处密度翻倍 | 每臂 3 条扫描线，间距 5，线宽 3 | 8.58 |
| **D 色散 X** | 12 条光线自焦点散开 | 每臂 ±7°，焦点空洞半径 5，线宽 2.5 | 10.26 |
| **E 字标内嵌** | 标就是字标里的那个 X | A 的形嵌入字标 X 位 | 见下 |

### E 的锁定度量（存档，Helvetica Neue 600 实测）

| 量 | 值 |
|---|---|
| 字高 cap height | 0.714 em |
| 标志墨占视框比例 | 0.707 |
| 标志框尺寸 | **1.01 em**（使墨高 = 字高，实测 100%） |
| 基线下移 | **0.148 em**（使墨中心 = 字高中心，实测偏差 0） |
| 左右负边距 | **−0.088 em**（抵消视框自带的 0.148 em 侧边距） |

> 换字体必须重测这三个数。`0.64em` 那类拍脑袋的值会让墨高只有字高的 63%，锁定立刻显得业余。

其余各组在 16px 同样需要简化版：A 锥度被抹平需加粗；C 扫描线并线产生摩尔纹需换实心 X；D 的 12 条线需减到 4 条。

## 色彩

界面为**单色**。画布渲染的是饱和的作品，chrome 里任何色相都会与作品抢视线，
所以主按钮、激活态、滑块、开关全部走 `--accent`：浅色模式近黑，深色模式近白。
**这不只是风格选择，是功能需要。**

### Token

| Token | Light | Dark | 用途 |
|---|---|---|---|
| `--bg` | `#FFFFFF` | `#0F0F0F` | 页面底 |
| `--surface` | `#F9F9F9` | `#171717` | 参数面板 |
| `--surface-2` | `#FFFFFF` | `#212121` | 输入框 / 按钮 |
| `--surface-3` | `#EFEFEF` | `#2B2B2B` | 悬停 / 滑轨 |
| `--border` | `#E5E5E5` | `#2F2F2F` | 分隔线 |
| `--border-control` | `#C6C6C6` | `#4D4D4D` | 控件描边 |
| `--text` | `#0D0D0D` | `#ECECEC` | 正文 |
| `--text-2` | `#5C5C5C` | `#A4A4A4` | 次级 |
| `--text-3` | `#6B6B6B` | `#949494` | 元信息 |
| `--accent` | `#0D0D0D` | `#ECECEC` | 主操作 / 激活 |
| `--accent-fg` | `#FFFFFF` | `#0F0F0F` | 强调色上的文字 |
| `--stage` | `#F2F2F2` | `#0A0A0A` | 画布衬底 |
| `--danger` | `#B42318` | `#F97066` | 校验失败 |

### 对比度

按浏览器实际渲染值复算，两种模式共 23 个文字目标：

| | 最低对比度 | 不达标项 |
|---|---|---|
| 浅色 | 5.06 | 0 |
| 深色 | 5.31 | 0 |

**已知取舍**：`--border-control` 的非文本对比度为浅色 1.71 / 深色 1.90，低于 WCAG 1.4.11 要求的 3.0。
这是所有极简描边系统（含 OpenAI 自己）的共同取舍。补偿方式是**焦点环用 `--text` 实色 2px**
（19.4 / 13.6，远超标准），键盘可达性不受影响。
若需严格合规，高对比描边变体为 `#8E8E8E` / `#6F6F6F`（3.28 / 3.20），代价是界面变硬。

### 两条硬规则

1. **激活态不靠颜色。** 去掉强调色后，选中状态一律用「实色填充 + 描边」表达，
   不依赖色觉也能分辨。参考预设卡片的激活样式。
2. **画布上方的文字按着色器背景亮度翻转，与界面主题无关。**
   由 `app.js` 计算背景亮度后加 `.light-canvas` 类控制。浅色界面 + 深色画布时若跟随界面主题，文字会看不见。

### 主题切换

默认跟随 `prefers-color-scheme`；用户手动切换后写入 `localStorage` 的 `rheo-theme`，
同时同步 `color-scheme` 与 `<meta name="theme-color">`。
`<head>` 内有一段内联脚本在首次绘制前读取偏好 —— 模块脚本是 defer 的，不加这段刷新会闪白。

## 字体

| | |
|---|---|
| 现状 | 系统 grotesque 栈（`Inter, -apple-system, "PingFang SC"`） |
| 正式建议 | Söhne / ABC Diatype / Neue Haas Grotesk；免费可用 Inter |
| 等宽 | `ui-monospace` —— 用于种子、HEX、读数、时间码等一切机器值 |
| 字标字距 | −0.035 em |

**机器值一律等宽，人读文案一律比例字体。** 这条贯穿全站：
种子、色值、FPS、分辨率、时间码属于前者；标题、说明、提示属于后者。

> 字形需要真正画出来。提案里的字标是用 Helvetica Neue 近似的，只够看比例和锁定关系。
> 正式做需选定 grotesque 后逐字调字偶距、改造关键字母的终端与字怀 —— 这一步是人手活。

## 语气

面向设计师和图形开发者，两边都要站得住。

- **说数值，不说形容词。** 「折叠场限制在 850×650」优于「性能经过优化」
- **承认做不到的。** 未实现、未对齐、有取舍的地方直接写出来，不含糊
- **不吹复刻。** 参考了什么就说参考了什么，可确认的与推测的分开写
- 中文为主，技术术语保留英文原词（shader、seed、WebGL），不强行翻译

**最重要的一条：`luxel.com` 属于 Luxel Corporation**（1974 年创立于加州，现址华盛顿州 Friday Harbor，
生产 X 射线与极紫外波段的超薄薄膜滤光片，为 NASA 供货）。域名注册于 1997 年，续费至 2027 年。

这家公司**做的是光学**。虽然是实体硬件而非软件、商标类别不同、五十年来也未涉足设计工具，
但「Luxel + 光」这个组合已经有人用了五十年。这是选这个名字必须接受的代价：
`.com` 永久拿不到，且在光学语境下存在概念混淆的可能。

### 标志

2×2 方格阵列**与微软的四方格标结构相近**（微软标为四个彩色方块，2×2，带间隙）。
本方案的区别在于：单色灰阶而非彩色、四格相邻无间隙、灰度呈单向递减而非四色并置。

**当前处置：暂不处理，上线前再评估。** 差异应当足以区分，但这是本方案风险最高的一点，
正式商标注册（尤其第 9 / 42 类）前必须由律师确认。在此之前标志按现状推进。
