# Rubric 工具逻辑评估

评估日期：2026-09-21。范围：配色模式、推荐与应用、浅深色方案、对比度检查、字体控制、本地保存、复制规范、键盘操作与滚动稳定性。

## 本轮已修复

| 问题 | 原因 / 影响 | 现在的行为 |
| --- | --- | --- |
| 解除联动没有真正生效 | 未记录深色参数，依然读取当前颜色和中性色参数；界面却称“单独设定” | 解除联动即锁定完整深色方案。所有当前配色控制只影响浅色；重新联动后同步。刷新保留锁定状态，导出如实说明 |
| 单色 / 多色切换丢颜色 | 缩减数量直接截断色板 | 记住六个色位及最近多色数量；恢复数量时取回先前的颜色 |
| 推荐色默认覆盖最后一个色位 | 多色方案无法指定目标 | 直接点击上方颜色胶囊选择应用目标，并显示描边；已去掉编号下拉框。主色仍作为推荐基准，胶囊的铅笔按钮用于手动取色。当前应用的推荐色也显示描边 |
| 自动适配偷偷改色 | 取色器显示原色，主题中经过对比度适配，同色系的明度可能被收近 | 增加“自动适配 / 保留原色”。默认延续自动适配；原色模式精确保留色值，仍报告对比度不足。导出区分原色和实际主题 token |
| 对比度结论范围过大 | 漏检悬停背景，把部分颜色检查概括成整体 WCAG AA 合规 | 检查页面、面板、输入框、悬停背景。默认元信息色略微调整以覆盖悬停；描边求解同时考虑全部背景。状态与导出只声明已检查的颜色组合 |
| 配色关系只看原色 | 实际生成的颜色可能已不同，提示与最终方案不一致 | 分别检查浅色、深色的实际强调色，并标注主题。低色度或明度已经明显分离时，不再只凭接近的色相提出冲突 |
| 字体预览的连续字重不可靠 | 本地 IBM Plex Sans 仅有 400 / 600 字体文件，Mono 仅有 400；其他设定会匹配或合成 | 保留用户设定和导出值，但在页面、导出中明确预览限制；不宣称每个字重都精确呈现 |
| 复制失败后无内容可供手动复制 | 原先临时文本框随后被删除，提示却要求用户手动选择 | 提供包含完整规范的手动复制弹窗 |
| 保存内容不校验 | 旧版本、损坏类型、空色板、越界数值可能造成不一致或渲染错误 | 恢复前规范化字段，限定合法色值与范围；旧的两色配置归入多色。保存失败会给出反馈 |
| 键盘和提示交互不完整 | 模式按钮缺少方向键行为；预览内提示容易被滚动区域裁切 | 模式支持方向键 / Home / End；检查说明可用鼠标或键盘在弹窗中完整查看 |
| 每次调字重都重算配色 | 字体调整不影响配色，仍重复进行生成和推荐运算 | 按配色参数缓存两套主题，按主色缓存推荐 |

上一轮对节点复用、重复推荐、模式简化与固定预览高度的修复继续保留。推荐按钮按固定槽位复用，额外节点会清理，不依赖强制恢复页面滚动。

## 产品边界与后续建议

- 目前是颜色 token / 字体参数生成器。若希望更直观地判断设计，应下一步增加真实组件预览（正文、按钮、输入框、悬停状态），而不仅看色块和数值。
- “深色锁定”是冻结当前结果，不是独立深色编辑器。如果需要分别精调两套主题，应增加明确的编辑目标切换，避免共用滑块含义不清。
- 推荐仍是基于主色的候选色，不是一次生成完整的 2–6 色方案。多色组合是否需要表达不同语义，仍由设计者决定；配色提示不是审美裁决。
- “保留原色”保住同色层次，但不保证所有颜色都适合放在任意背景上做交互控件。检查会如实提示，不能同时承诺原色不变和所有用途都达标。
- 若要准确比较 300–800 的每一档字重，需要补齐字体文件或使用支持该区间的可变字体；当前没有新增字体或依赖。
- 尚不包含自动生成完整 CSS 样式表、语义化状态色或整页无障碍检查。

## 验证与依据

- 54 项自动测试通过，覆盖色彩生成、同色推荐、重复节点回收、色板恢复、深色冻结与恢复、无效存储、原色保留、悬停对比度、导出状态与检查范围。
- 浏览器实际验证：推荐应用到第 2 个色位时其他色位不变；单色 / 多色往返保留四个色值；深色锁定后浅色变化、深色不变；刷新恢复锁定与数量；恢复联动后重新同步；对比度说明弹窗可打开；方向键切换模式与重置正常。窄窗口真实鼠标交替点击推荐 12 次，scrollY 始终为 1060，推荐数固定为 10，焦点保留。
- 复制失败兜底已完成代码与界面逻辑检查，没有人为禁止系统剪贴板权限来强制触发该分支。
- 对比度参考：[W3C 文本对比度](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html)、[W3C 非文本对比度](https://www.w3.org/WAI/WCAG22/Understanding/non-text-contrast.html)。检查通过并不等于完整页面符合 WCAG AA。

## 推荐算法与字体联动追加评估

### 推荐色

- 分类改为“对比色 / 同色阶”。前者包含互补、分裂互补和三分候选，强调色相差异；后者保持同一色系，按明度形成色阶。这些名称不意味着候选满足文字对比度要求。
- 接近中性的颜色没有稳定的色相。之前仅一档 RGB 变化就可能把整组推荐换色；现在低色度时提供固定色相的“彩色点缀”，不再把它们称为灰色的“互补色”。
- 低饱和主色不再被统一抬到高色度；保持原来的柔和倾向，并对每个目标色相做色域收敛。
- 浅粉色等高明度主色原先可能被限幅推回相近明度。现在会检查量化后的实际颜色，必要时重新寻找不会触发当前配色冲突规则的明度。
- 遍历 144 个色相 / 明度 / 色度组合、共 720 个对比候选，未发现重复候选或工具自身提示的两色冲突。这是有限样本验证，不是普遍审美保证。
- 候选与非目标色位已选颜色感知距离过近时置灰；目标色位当前颜色不参与排除，所以重复点击不会变成不可用。
- 自动适配主题仍可能改变原色的层次，主题检查继续独立执行。需要严格保留深浅色阶时使用“保留原色”。

分类概念参考 [Adobe 配色关系](https://www.adobe.com/creativecloud/design/hub/guides/sets-of-2-colors-that-go-great-together.html)。算法为本项目实现，没有引入该网站的代码。

### 字体推荐联动

- 新增“推荐联动”按钮，默认关闭。开启时以当前正文为基准对齐预设，之后四行中的任何一行都可以作为拖动入口。
- 字号比例：正文 / 强调 / 标题 / 等宽为 1 / 1 / 1.6 / 14÷15，显示值取整数；字重相对正文的差值为 0 / +200 / +250 / 0。
- 字号和字重分别联动：改字号不会顺便改字重。字号同比例缩放，字重等差增减，不直接把字重当作字号比例缩放。
- 联动时按整组可用范围限制滑块，避免某一行单独撞上限而破坏关系。关闭联动保留当前值，恢复独立调节范围。
- 保存未取整的字号基准，刷新不会累计取整误差；导出包含最终字号、字重和联动策略。
- 这组关系源自工具现有的 15 / 15 / 24 / 14 与 400 / 600 / 650 / 400 初始值，是可退出的预设，不是通用规范。[Carbon 的字型体系](https://carbondesignsystem.com/elements/typography/type-sets/)也按使用场景定义不同的字型集合，而非只有唯一关系。
- 字体本身可用字重的限制仍存在；联动改变的是设计参数，不会凭空补齐字体文件。

本轮新增 7 项回归测试，总计 61 项通过。浏览器验证了真实鼠标拖动字号和字重、上限、关闭后独立调节、刷新恢复，以及重复候选置灰；拖动时页面位置和焦点保持稳定。

颜色选择交互更新：验证了切换胶囊后仅修改选中目标，推荐色与胶囊均显示选中描边；真实点击前后 scrollY 均为 1047，候选总数固定为 10。当前共 62 项自动测试通过。

## 小字号与字重组合提示

新增“排版建议”，在对应字体用途旁显示可点击说明，并同步写入导出的规范。当前经验阈值为：字号不超过 14px 且字重至少 700，或字号不超过 16px 且字重至少 800 时提示“小字偏重”；字号不超过 14px 且字重低于 400 时提示“小字偏细”。提示不改变参数，不阻止导出，不属于 WCAG 不合格判定。

这些阈值是本工具的可读性启发式规则，不是外部标准规定的字号 / 字重禁配表。短标签使用粗体可能合理；需要结合目标字体、汉字笔画、字间距、使用场景和实际对比度观察。参考 [W3C 对比度说明](https://www.w3.org/WAI/WCAG21/Understanding/contrast-minimum)与 [Carbon 字型集合](https://carbondesignsystem.com/elements/typography/type-sets/)。

验证：新增阈值、默认配置不误报、联动触发 / 调整消除以及导出建议的测试，总计 64 项通过。实际浏览器中，联动的小字重字组合触发提示，增大字号后消失，说明弹窗可完整打开；页面无运行错误。
